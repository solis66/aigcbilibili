# 本地开发指南（VS Code + Docker）

> 面向「要改这个项目的代码」的人。只想跑起来看效果 → 看根目录 [快速开始.md](../../快速开始.md)。
> 本项目是 **Spring Cloud 微服务 + Vue3 前后端分离**：6 个后端服务、1 个前端、6 个中间件（v2 起，已移除
> Nacos / Zipkin / xxl-job 三个从未生效的组件）。

---

## 1. 两种跑法，先选一种

| | 应用在哪 | 中间件在哪 | 适合 |
|---|---|---|---|
| **A. 全容器** | Docker | Docker | 只想看效果、演示、验收；一条命令，13 个容器 |
| **B. 混合（推荐开发）** | 宿主机（VS Code 调试） | Docker | 要断点、要热更新、改完立刻见效 |

两种方式的中间件完全相同，切换只影响「后端进程跑在哪」。下面的 VS Code 配置按 **B** 准备。

## 2. 需要装的软件

| 软件 | 版本 | 说明 |
|---|---|---|
| JDK | **17**（编译目标 Java 8） | 项目 `maven.compiler.target=8`，但用 17 跑没问题；容器里是 8 |
| Maven | 3.9+ | 或用 VS Code 内置（Java 插件用的也是本机 mvn） |
| Node.js | **16 或 18** | 前端是 Vue CLI 5 + webpack，Node 20+ 可能有 openssl 兼容问题 |
| Docker Desktop | 4.x+（WSL2 后端） | 内存分配 **≥ 10GB**（13 容器，实测常驻 9~11GB） |
| Git | 任意 | — |

> Windows 上必须确认 Docker 分配的内存够：Docker Desktop → Settings → Resources → Memory。
> 实测 11.4GB 时全套 13 容器可跑；低于 10GB 建议用「lite 子集」（见快速开始 §4）。

## 3. VS Code 插件（`.vscode/extensions.json` 已配好，打开工作区会提示一键安装）

| 插件 ID | 干什么 | 不装会怎样 |
|---|---|---|
| `vscjava.vscode-java-pack` | Java 语言支持（含 Maven、调试器、测试） | 打不开 Java 项目、无法断点 |
| `vmware.vscode-boot-dev-pack` | Spring Boot 专属：`application.yml` 补全、Bean 跳转、运行面板 | 配置文件要手写键名 |

| `Vue.volar` | Vue 3 单文件组件语法支持 | `.vue` 文件没有补全 |
| `dbaeumer.vscode-eslint` | 前端 lint（项目自带 eslintConfig） | 保存时不会提示问题 |
| `ms-azuretools.vscode-docker` | 容器/镜像/日志可视化 | 只能命令行看日志 |
| `redhat.vscode-xml` | 8 个 `pom.xml` 的补全与校验 | 只能手写 XML |
| `humao.rest-client` | 直接在编辑器里发 HTTP 请求做冒烟 | 只能 curl |

**装完必须做一次**：`Ctrl+Shift+P` → `Java: Clean Java Language Server Workspace` → Restart，
让 Java 语言服务重新按 `pom.xml` 构建索引。首次会下载依赖，几分钟。

## 4. 混合模式：三步起环境

### 4.1 起中间件（容器）

```powershell
cd docker
copy .env.example .env      # 首次；Linux/macOS 用 cp
docker compose -f docker-compose.yml -f docker-compose.middleware-host.yml up -d `
    mysql redis minio minio-init rocketmq-namesrv rocketmq-store-init rocketmq-broker elasticsearch
```

VS Code 里等价于 **Tasks: Run Task → `middleware:start`**。

这套 override 只做两件事（不改主 compose）：
- redis 发布到宿主 **16379**（宿主 6379 常被本机 redis 占用）
- rocketmq-broker 用 `broker.host.conf`，把 brokerIP1 注册成 `127.0.0.1` 供宿主回连

### 4.2 起后端（VS Code 调试）

```
运行和调试面板 → 选择「⑥ search (8201)」→ F5
```

每条配置都设了 `cwd = docker/local-run` 和
`--spring.config.additional-location=file:./conf/<服务>/`，指向宿主专用的覆盖配置
（把容器名换回 127.0.0.1、端口换成本机映射端口）。

**推荐启动顺序**：`② notice` → `③ user-center` → `④ video` → `⑥ search` → `⑤ chat` → `① gateway`。
gateway 最后起，避免前端先连上网关而后端还没好。

要一起起：选 **「全部后端（6 个）」** 复合配置（一次起 6 个 JVM，内存约 4GB，谨慎）。

### 4.3 起前端

```powershell
cd vue/labilibili
npm install          # 首次
npm run serve        # http://localhost:2023
```

前端默认代理线上域名；要让 dev server 打到本机网关：

```powershell
$env:VUE_APP_API_TARGET='http://localhost:8200'
$env:VUE_APP_WS_TARGET='http://localhost:1688'
npm run serve
```

（VS Code 里可用 **Tasks: Run Task → `frontend:serve`**，但环境变量需在 tasks 里另配。）

## 5. 改完代码怎么生效

| 改了什么 | 怎么做 |
|---|---|
| Java 代码 | 混合模式下直接重启该服务的调试会话（秒级） |
| `java/*/src/main/resources/application.yml` | 同上；注意外置配置优先级更高，改 classpath 可能被 `conf/` 覆盖 |
| `docker/config/*/application.yml`（容器用） | 只影响全容器模式；改了要 `docker compose restart <服务>` |
| `docker/docker-compose.yml` | `docker compose up -d` 会自动重建变更的服务 |
| 服务代码（全容器模式） | `docker compose build <服务> && docker compose up -d <服务>`（单服务约 2~4 分钟） |
| 前端代码 | dev server 热更新，无需重启 |

## 6. 排障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 后端启动报 `Connection refused: 127.0.0.1:16379` | 中间件没起或端口不对 | 确认 `middleware:start` 跑过；redis 必须用 **16379** |
| 后端连 MySQL 失败 | 容器还在初始化（首次要跑建表脚本） | `docker compose ps` 等 mysql 变 healthy，约 40s |
| 前端全 404 / 502 | 网关没起或路由目标未启动 | 先确认 `http://localhost:8200/getFirstPageVideo/1` 有响应 |
| 搜索返回 200 但结果空 | ES 里没有索引（新库还没有任何视频） | 上传一条视频，等 1 分钟（`@Scheduled` 每分钟同步一次） |
| 搜索报 600 / index_not_found | 同上，索引尚未创建 | 同上；或手动 `GET /search/test` 触发一次同步 |
| 头像/封面 404 | MinIO 桶没建（`minio-init` 没跑） | `docker compose up -d minio-init` |
| 上传视频 500 | `var/temp` 目录不存在（相对路径） | 混合模式脚本会预建；直接用 IDE 时在 `docker/local-run` 下建 |
| 容器创建即失败、无日志、只有 `bind: ... forbidden` | Windows 保留端口段 | `netsh int ipv4 show excludedportrange protocol=tcp` 查，改 `docker/.env` 端口 |
| 想全部重来 | — | `docker compose down -v`（会删库数据） |

## 7. 目录速记

```
java/                      Maven 多模块（common / gateway / notice / user_center / video / chat / search）
  common/                  公共模块：Feign 客户端、Result、全局异常、MyBatis 填充器
docker/
  docker-compose.yml       主编排（13 个常驻容器）
  docker-compose.middleware-host.yml  混合模式 override（中间件在容器、应用在宿主）
  config/<服务>/            容器内使用的外置配置（优先级高于 classpath）
  local-run/conf/<服务>/    宿主调试使用的外置配置（127.0.0.1 + 本机映射端口）
  local-run/*.ps1          混合模式的一键脚本
vue/labilibili/            前端源码（构建与本地运行都只用这一份）
```

> 注意：`vue/src` 是上游遗留的另一份分叉副本，**不参与构建**，改动无用。
