# 混合模式运行手册 —— 中间件在 Docker、应用在宿主

> 面向「我要在本地改代码并调试」的场景：**中间件全部放 Docker，6 个 Spring Boot 后端与 Vue 前端跑在 Windows 宿主上**。
> 2026-09-22 在本机实测通过：中间件 8 容器 healthy → 宿主 **notice + gateway** 起来 → 浏览器/curl 走 `8200 → 30000 → MySQL` 返回 `{"code":200,...}`。
>
> ⚠️ **默认跑法不是本文**：只想「跑起来、点得动」就用《本地部署操作手册.md》（全套 16 容器，`docker compose up -d`）。
> 本文只在你要**断点调试 Java / 改代码立刻生效**时才用。两套共用同一份 compose 与同一批命名卷，可来回切（见 §11）。

---

## 0. 一句话说明两套方式的差别

| | 全套容器（docker/本地部署操作手册.md） | 混合模式（本文） |
|---|---|---|
| 中间件 | Docker | Docker（**复用同一份 compose**） |
| 6 个后端 | Docker | **宿主**（IDE 里点运行 / `run-backend.ps1`） |
| 前端 | Docker(nginx) http://localhost:2023 | **宿主 dev server** http://localhost:2023 |
| 改代码后 | 重建镜像（分钟级） | 重启进程 / 热更新（秒级） |
| 额外内存 | 约 7.4 GiB 全给 Docker | Docker 约 4.6 GiB，宿主再吃约 2~3 GiB |

混合模式**没有改动 `docker-compose.yml`**，只加了一个 override 文件 `docker/docker-compose.middleware-host.yml`。

## 3. 起中间件

```powershell
cd C:\Users\20931\Desktop\aigcbilibili\docker\local-run

.\start-middleware.ps1            # 全套中间件（含 ES / zipkin / xxl-job-admin）
.\start-middleware.ps1 -Core      # 精简：只起 mysql/redis/minio/rocketmq，省约 2.5GB
```

等价的原始命令（不依赖脚本）：

```powershell
cd C:\Users\20931\Desktop\aigcbilibili\docker
docker compose -f docker-compose.yml -f docker-compose.middleware-host.yml up -d `
    mysql redis minio minio-init rocketmq-namesrv rocketmq-store-init rocketmq-broker `
    elasticsearch zipkin xxl-job-admin
```

**只比全套容器多了两处打开**（都写在 override 文件里，主 compose 没动）：

1. **redis 发布到宿主 16379**。`docker-compose.yml` 里 redis 刻意不发布端口，因为宿主 6379 被本机常驻 redis-server 占着（D-11）。混合模式下后端在宿主，必须能连上容器 redis，所以发布到 16379。
2. **broker 换用 `middleware/broker.host.conf`，`brokerIP1=127.0.0.1`**。`brokerIP1` 是 broker 注册到 namesrv 的**回连地址**，客户端拿到它之后直接去连。容器模式下它是容器名 `rocketmq-broker`，宿主解析不了这个名字 → 生产者/消费者连不上 broker（而且启动不报错，只有发消息才超时，很难查）。改成 `127.0.0.1` 后宿主回连 `10911` 即可。

实测（本次）：8 个常驻容器全部 `Up (healthy)`，宿主端口探测 3306 / 16379 / 9000 / 9001 / 9876 / 10911 / 9200 / 9411 / 8080 **全部可连**。

## 5. 跑后端

**每个服务开一个 PowerShell 窗口**：

```powershell
cd C:\Users\20931\Desktop\aigcbilibili\docker\local-run
.\run-backend.ps1 -Service gateway     # 127.0.0.1:8200
.\run-backend.ps1 -Service notice      # 127.0.0.1:30000
.\run-backend.ps1 -Service user-center # 127.0.0.1:3000
.\run-backend.ps1 -Service video       # 127.0.0.1:10201   （大服务，可 -Heap 768m）
.\run-backend.ps1 -Service chat        # 127.0.0.1:1688
.\run-backend.ps1 -Service search      # 127.0.0.1:8201     （需要 ES + xxl-job-admin）
```

脚本替你做四件事：

| 做的事 | 为什么 |
|---|---|
| `--spring.config.additional-location=file:./conf/<service>/` | 配置优先级高于 jar 内 classpath；**只写与默认值不同的键**，其余（含网关 routes）自动沿用 |
| `--server.port=<端口>` | 命令行参数优先级最高，能盖过环境变量。踩过的坑：Windows 上若有 `SERVER_PORT` 之类变量，服务会去抢一个莫名其妙的端口 |
| 工作目录固定到 `docker/local-run/` + 预建 `var/temp` | video 的 `multipart.location=var/temp` 是相对路径；日志也统一落 `logs/<service>/` |
| `-Duser.home=./.home` | D-07：防 RocketMQ 客户端日志写进真实用户目录（实测 `.home/logs/rocketmqlogs/` 确实在那） |

### 本地配置到底改了什么

`docker/local-run/conf/<service>/application.yml`（gateway 是 `application-dev.yml`，因为它 classpath 走 dev profile）。全部差异只有一类：

| 键 | 容器模式 | 混合模式 |
|---|---|---|
| `spring.datasource.url` | `jdbc:mysql://mysql:3306/...` | `jdbc:mysql://127.0.0.1:3306/...` |
| `spring.redis.host/port` | `redis` / 6379 | `127.0.0.1` / **16379** |
| `rocketmq.name-server` | `rocketmq-namesrv:9876` | `127.0.0.1:9876` |
| `minio.url` | `http://minio:9000` | `http://127.0.0.1:9000` |
| `elasticsearch-client.hosts` | `http://elasticsearch:9200` | `http://127.0.0.1:9200` |
| `xxl.job.admin.addresses` | `http://xxl-job-admin:8080/...` | `http://127.0.0.1:8080/...` |
| `zipkin.base-url` | `http://zipkin:9411` | `http://127.0.0.1:9411` |

> 一律用 `127.0.0.1` 而不是 `localhost`：Windows 上 `localhost` 可能先解析到 IPv6 `::1`（项目容器里已经因为同类问题踩过 FIX-7）。
>
> ⚠️ 配置目录故意叫 **`conf/` 而不是 `config/`**：Spring Boot 默认会**通配加载** `file:./config/*/`，若放在 `config/<service>/`，6 份配置会互相串味（每个服务都读到别人的键）。`conf/` 不在默认搜索路径里，只有显式 `additional-location` 才会读到。

### 用 IDEA 跑（等价做法）

Run/Debug Configurations 里对每个模块：

- **Working directory**：`C:\Users\20931\Desktop\aigcbilibili\docker\local-run`（脚本固定了它，IDE 默认是 `java\<module>`，不设就读不到 `./conf/`）
- **VM options**：`-Duser.home=<repo>\docker\local-run\.home -Dfile.encoding=UTF-8`（JDK 17 再加那 6 条 `--add-opens`）
- **Program arguments**：`--spring.config.additional-location=file:./conf/<service>/ --server.port=<端口>`

## 6. 跑前端（可选）

只调后端的话可以跳过本节，直接用 curl / Knife4j 打网关。

```powershell
cd C:\Users\20931\Desktop\aigcbilibili\docker\local-run

.\setup-frontend.ps1      # 首次执行：修 webpack pin + npm install
.\start-frontend.ps1      # 起 dev server（默认 2023）
```

- `setup-frontend.ps1` 会把 `vue/labilibili/package.json` 里被硬锁的 `"webpack": "4.0.0"` 改成 `"^5.89.0"`（备份为 `package.json.bak`）。这是**上游 package.json 的 bug**：`@vue/cli-service ~5.0.0` + vue-loader 17 走 webpack 5 API，而 webpack 4 里没有 `webpack/lib/rules/BasicEffectRulePlugin` → `serve/build` 直接崩。镜像构建层里也是这么修的（`docker/frontend/Dockerfile` FIX-2），与包管理器无关。
- `start-frontend.ps1` 在启动前设两个环境变量（`vue.config.js` 支持，未设时行为不变、仍代理线上）：
  - `VUE_APP_API_TARGET=http://127.0.0.1:8200` → `/api` 转发宿主 gateway 并去掉 `/api` 前缀；
  - `VUE_APP_WS_TARGET=http://127.0.0.1:1688` → `/wschat` 转发宿主 chat 的 WebSocket。
- 浏览器打开 **http://localhost:2023**。

**两个坑**：

1. dev server 端口和前端容器**都是 2023**，不要同时起（脚本会预检并提示 `docker compose stop frontend` 或换 `-Port`）。
2. **不要用「前端容器 + 宿主网关」的混搭**：容器内 nginx 的上游写的是 `gateway:8200`（容器名），指的是容器网络里的网关，够不到宿主上的 gateway。真要这么混，得改 `docker/frontend/nginx.conf` 的 upstream 到 `host.docker.internal:8200`。

## 8. 排障

| 现象 | 根因 / 处置 |
|---|---|
| 后端连上了「不在预期」的 redis | 忘了改 `spring.redis.port`。宿主 6379 是本机常驻 redis-server，容器 redis 在 **16379**。两处（`middleware-host.yml` 与本文件 §5 的 yml）必须一致。 |
| 服务不按配置的端口起，去抢一个陌生端口 | Windows 上存在 `SERVER_PORT` / `server.port` 之类的环境变量，优先级高于配置文件。脚本已用 `--server.port=` 钉死（命令行参数优先级最高）。 |
| `.ps1` 一跑就报「表达式或语句中包含意外的标记」/ 中文变乱码 | 脚本被存成了**无 BOM 的 UTF-8**，PowerShell 5.1 按 GBK 解码 → 直接语法错误。`docker/local-run/*.ps1` 全部存成 **UTF-8 with BOM**（首三字节 `EF BB BF`）。用 VS Code 时注意别把 BOM 去掉。 |
| notice / video 一发消息就 timeout，启动却正常 | RocketMQ `brokerIP1` 还是容器名。确认起容器时带上了 `-f docker-compose.middleware-host.yml`。 |
| `Port 2023 already in use` | 前端容器还在跑，或者上一次 dev server 没退干净。`docker compose stop frontend` 或 `-Port 2024`。 |
| 端口被占（3306/9876/10911/9000…） | 本机另有服务占用。改 `docker/.env` 里的 `*_HOST_PORT`，同时改 `conf/<service>/application.yml` 里对应地址。 |
| 想让后端也用 JDK 8 | `.\run-backend.ps1 -Service notice -JavaExe 'D:\jdk\jdk1.8.0_xxx\bin\java.exe'` |
| 改了 conf 里的配置 | 直接 Ctrl+C 重启该服务即可（配置文件是启动时读的，不需要重新构建）。 |

## 11. 两套模式来回切换（2026-09-22 实测）

两套共用同一份 `docker-compose.yml` 与同一批命名卷（`aigcbilibili_*`），切换**不会丢数据**。

### 全 Docker → 混合模式

```powershell
cd C:\Users\20931\Desktop\aigcbilibili\docker\local-run
.\stop-middleware.ps1 -Remove          # 等价 docker compose down（保留命名卷）
.\start-middleware.ps1                 # 带 override 起中间件
.\run-backend.ps1 -Service gateway     # 每个服务一个窗口
```

### 混合模式 → 全 Docker

**必须先杀掉宿主上的 java**，否则 8200 / 30000 被占，容器起不来（报 `port is already allocated`）。
`docker compose up -d` 不会替你处理这件事：

```powershell
# 1) 找宿主上由本套脚本起的 java（用命令行里的 local-run 路径辨认，别误杀 IDEA）
Get-CimInstance Win32_Process -Filter "Name='java.exe'" |
  Where-Object { $_.CommandLine -like '*docker\local-run*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

# 2) 确认端口已释放
foreach ($p in 8200,30000) { Get-NetTCPConnection -LocalPort $p -State Listen -ErrorAction SilentlyContinue }

# 3) 用主编排全量起来（不要带 override 文件）
cd C:\Users\20931\Desktop\aigcbilibili\docker
docker compose down
docker compose up -d
```

### 切回全 Docker 后怎么确认「干净了」

| 检查项 | 期望 |
|---|---|
| `docker compose ps` | 16 个常驻容器 Up，除 `minio` 外全部 `(healthy)` |
| 宿主 **16379** | **CLOSED** —— 说明 override 没残留（redis 只在容器网络内 `expose 6379`） |
| `http://localhost:2023/api/getNotice/getNoticeCount/1` | `{"code":200,...}` |
| `docker stats` 的 `MemPerc` | 全部 < 80%（实测最高 `xxl-job-admin` 78.9%、`rocketmq-broker` 75.9%） |
