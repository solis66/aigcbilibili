# Docker 安装指引（Windows 11 家庭版）

> **v2 状态（2026-10-25）**：Nacos / Zipkin+Sleuth / xxl-job 已从项目中**移除**，
> 容器由 16 个降为 **13 个常驻**。本文中凡提到这三个组件的端口、控制台、账号、
> 排障步骤（尤其是「去 xxl-job 控制台补执行器分组」一类）**均已作废**，
> 以 `README.md` 的「v2 变更记录」与根目录 `快速开始.md` 为准。


> 目标机器：Windows 11 **家庭版** 中文版（Build 26200）、16GB 内存、`HypervisorPresent=True`、
> **无 WSL 发行版**、**未安装 Docker**、**当前用户非管理员**。
> 本指引覆盖两条路线，任选其一：
> **路线 A（推荐）Docker Desktop + WSL2 后端** ／ **路线 B（更轻）WSL2 + Docker Engine（不开 Desktop）**。
>
> ⚠️ **提权点**：两条路线都需要**管理员权限**执行安装命令（`wsl --install`、安装包、`wsl --set-default-version` 等）。
> 当前用户非管理员，须找管理员账号或临时提权。安装完成后，日常使用**不需要**管理员。

---

## 0. 装前检查（PowerShell，普通权限即可）

```powershell
# 虚拟化是否可用（应为 True）
(Get-CimInstance Win32_ComputerSystem).HypervisorPresent

# 是否已有 WSL（家庭版默认未装）
wsl --status

# 内存
(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB
```

若 `HypervisorPresent=False`，需先在 BIOS 打开虚拟化（VT-x/SVM）。

## 1. 镜像加速器（**必做**：访问 Docker Hub 在国内很慢）

先建/改 Docker 守护进程配置 `daemon.json`。**路线 A** 的位置为
`C:\Users\<用户名>\.docker\daemon.json`（Docker Desktop → Settings → Docker Engine 里也能改）。
**路线 B** 的位置为 `/etc/docker/daemon.json`（WSL 内）。

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://mirror.baidubce.com",
    "https://hub-mirror.c.163.com"
  ]
}
```

> 说明：加速器地址会变动，若某个失效请替换为当前可用的公共镜像。改完**重启 Docker**（路线 A：右键托盘 → Restart；
> 路线 B：`sudo service docker restart`）。

**关于 Elasticsearch**：本项目用 **Docker Hub 的 `elasticsearch:7.13.3`**，**不要**用 `docker.elastic.co`（国内常不可达）。
compose 已按此配置，无需改动。

## 2. 路线 A：Docker Desktop + WSL2 后端（推荐，图形化管理）

### 2.1 安装 WSL2（需管理员）
```powershell
# 一次性安装 WSL2 + 默认发行版（Ubuntu），完成后按提示重启
wsl --install
# 重启后确认
wsl --set-default-version 2
wsl --status
```

### 2.2 安装 Docker Desktop
1. 下载：https://www.docker.com/products/docker-desktop/（选 **Windows** 版）。
2. 运行安装包（**需管理员**），勾选 **Use WSL 2 instead of Hyper-V**。
3. 首次启动 → Settings：
   - **General**：勾选 *Use the WSL 2 based engine*。
   - **Resources → WSL Integration**：启用你的发行版（如 Ubuntu）。
   - **Docker Engine**：粘贴 §1 的 `daemon.json` 内容。
   - **Resources → Advanced**：建议给 Docker 分配内存 ≤ 8GB（16GB 机器要给 OS/IDE 留余量）。
4. 验证：
```powershell
docker version
docker compose version
```

> 家庭版注意：若提示需要 WSL 更新，执行 `wsl --update` 后重启 Docker Desktop。

## 3. 路线 B：WSL2 + Docker Engine（不开 Desktop，更省内存）

### 3.1 安装 WSL2 与发行版（需管理员）
```powershell
wsl --install -d Ubuntu
# 重启，设好 Ubuntu 用户密码
wsl --set-default-version 2
```

### 3.2 在 Ubuntu 内安装 Docker Engine
```bash
# 在 WSL( Ubuntu ) 里执行
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER     # 免 sudo（重登生效）
```
把 §1 的 `daemon.json` 写到 `/etc/docker/daemon.json`，然后 `sudo service docker start`。

### 3.3 让 Windows 侧可访问 WSL 的端口
在 WSL 内，Docker 发布的端口通常可经 `localhost` 从 Windows 访问。若不通，用镜像网络模式：
在 `%UserProfile%\.wslconfig` 加：
```ini
[wsl2]
networkingMode=mirrored
```
`wsl --shutdown` 后重开。

> 若必须从 Windows PowerShell 调用 `docker`，可在 WSL 内 `sudo update-alternatives` 或把 `docker` 暴露到
> Windows PATH；更简单的做法是**进入 WSL 后直接在本项目目录运行 `docker compose`**。

## 4. 验证安装并首次启动本项目

```bash
# 进入项目（Windows 盘符在 WSL 下为 /mnt/c）
cd /mnt/c/Users/20931/Desktop/aigcbilibili/docker      # 路线 B（WSL 内）
# 或 Windows PowerShell 下（路线 A）：
#   cd C:\Users\20931\Desktop\aigcbilibili\docker

copy .env.example .env        # Windows: copy ；WSL/Linux: cp .env.example .env

docker compose build          # 首次构建（较久，镜像拉取以小时计；务必先配加速器）
docker compose up -d
docker compose ps             # 期望：全部 Up / healthy
```

|---|---|
| 前端 | http://localhost:2023 |
| 网关直连 | http://localhost:8200 |
| MinIO 控制台 | http://localhost:9001（minioadmin / minioadmin） |

## 5. 首次耗时与排障

| 场景 | 预期 |
|---|---|
| 镜像加速器生效 | 拉取 + 全量构建 ≈ 30~60 分钟 |
| 境外源（≈43KB/s） | 可能 **>2 小时**，务必配加速器 |

**常见问题**
- `wsl --install` 报错/卡住：`wsl --update` 后重试；某些家庭版需先在「启用或关闭 Windows 功能」勾选
  *虚拟机平台* 与 *适用于 Linux 的 Windows 子系统*（需管理员，改完重启）。
- 磁盘占用大：镜像 + 卷数 GB 级；`docker system df` 查看，`docker builder prune` 清理构建缓存。
- 内存吃紧：用 **lite 子集**（见 `README.md` §2），或调小 Docker Desktop 分配给 WSL 的内存。
- 端口冲突：改 `docker/.env` 里对应 `*_HOST_PORT`（**不要改 compose 文件**）。

## 6. 卸载 / 回滚（如需）

- 路线 A：Docker Desktop → Settings → 卸载；`wsl --unregister Ubuntu` 可移除发行版。
- 路线 B：`sudo apt-get purge docker-ce docker-ce-cli containerd.io`；`sudo rm -rf /var/lib/docker`。
- 本项目：`docker compose down -v` 清理容器与数据卷；Docker 资产目录可整目录删除后从版本库恢复。

> 本指引**未在本机实测**（本机无 Docker/无 WSL 发行版/非管理员）。请按步骤执行，如遇版本差异以官方文档为准。
